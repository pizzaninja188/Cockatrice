# Issue tracker

GitHub Issues is the sole source of truth for current work, priorities, status, and dependencies.
Query the live tracker before selecting or planning work, then reconcile the selected issue with
current code and Git history. Create an issue for new work and close it with the implementing commit,
pull request (`Fixes #N`), or a comment linking the commit and verification evidence.

This file remains a stable pointer for historical source comments that refer to `docs/issues.md #N`;
legacy `#N` numbers are the same GitHub issue numbers. It must not become a second task list.
